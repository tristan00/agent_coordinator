## Active-work invariant

After every committed evaluation, an admitted, nonterminal task without a verified explicit user stop has a runnable transition or a valid in-flight action with a bounded checkpoint, a concrete prerequisite with an accountable owner and observable release condition, or a durable recovery action with a due time. Persist run, task, stage and visit identity, the typed cause, owner, release condition, and any due time. Reevaluate on restart, prerequisite changes, and deadlines. Keep concurrent causes and choose the displayed cause deterministically.

Count committed state transitions, reservation changes, verified execution checkpoints, and recovery phase changes as progress. Track scheduler heartbeat and repeated observations separately. Apply watchdog thresholds to each disposition's expected checkpoint. Preserve approval gates, recorded limits, access decisions, and worker fences. Terminal and archived work leave active accounting. Downstream work awaiting an unsuccessful upstream still needs a disposition.

## Fixture scope and handoff

- Capability recurrence uses simulated worker results and fixed blocker timestamps. The expected baseline trace includes `blocker_recovery_scheduled`, `supervisor_recovery_created`, `supervisor_recovery_completed`, and exactly one `supervisor_recovery_reopened`. The reopened repair has no due recovery in the persisted incident model and repeated evaluations yield no claim. An independent task in a disjoint workspace can still claim. LIVE-05 should require a durable, due action on the same incident while preserving reviewed release, recorded budgets, and the original task's incomplete state.
- The pause persistence fixture invokes the task action as an authorized hold in the test setup. It checks dependency release, unrelated dispatch, reopen, and explicit resume. The historical actor label alone leaves provenance unresolved. LIVE-02 needs positive checks for operator and coordinator holds and negative authorization checks that require worker requests to leave state unchanged across direct and scoped entry points.
- The scheduler fixtures run the actual scheduler against disposable SQLite stores. A malformed persisted stage reaches the recovery transition and yields `Unknown current stage` on successive ticks. The tentative sibling transition rolls back with the tick. A metadata write fault also rolls back the pending claim and events. Removing each injected fault allows the scheduler to proceed. LIVE-06 should require unrelated progress during a scoped error and atomic rollback when the whole store is unavailable.
