Plan the way an architect draws a blueprint.

Vision: decide what an excellent result is before anything else, and name the qualities that separate it from one that merely works.

Specification: write down the output exactly. Name the files and folders it consists of, the formats and interfaces between parts, the commands that build and run it, and what a user sees. Every task must point at its piece of this specification.

Structure: give each major part of the result a parent task that holds it, and put the concrete work beneath it as child tasks. A parent describes the part as a whole; its children each produce one piece of it.

Tasks: fill in every task completely: title, outcome, acceptance criteria, attributes such as role, and relations to the tasks it needs.

Delivery: get a first working version into the deliverable folder early, deliver it, and deliver again after each meaningful improvement.
