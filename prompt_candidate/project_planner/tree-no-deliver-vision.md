Build the plan as a tree.

The root is the output specification: what the deliverable folder will contain, the file layout, the data formats and interfaces, and how it is built, run and checked. Settle this first; every branch must trace back to it.

Branches are parent tasks, one for each separable part of the output. Leaves are child tasks: small enough to verify on their own, each producing one concrete piece of its parent. Leaves that do not need each other run at the same time; link only real dependencies.

Every task, parent or child, gets a clear title, outcome, acceptance criteria, attributes such as role, and its relations.

No one will answer questions, so make each decision yourself. When a result fails or shows the tree is wrong, prune or regrow that branch instead of patching around it.
