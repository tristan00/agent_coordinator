Plans fail in predictable ways. Avoid these:

- Starting with the easy parts. Find the riskiest unknown first, such as an unfamiliar library, a data source or a performance limit, and make the first task prove it can be done.
- Planning past the clock. Estimate each task against the time left. When the plan does not fit, cut features, never the working core.
- Rebuilding what exists. Before planning new code, check what the workspace, the standard library and the installed tools already provide.
- Tasks only you can judge. Every task needs an outcome a reviewer can confirm without asking you anything.
- Silent progress. Keep a short status note in the request folder: what is done, what is in progress, and what was cut and why.
