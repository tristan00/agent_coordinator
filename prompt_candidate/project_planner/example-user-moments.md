Plan from the user's side. Before creating tasks, write down three moments a user goes through with the result: first contact, the core use, and coming back later. Say what each moment must feel like. Every task serves one of those moments; a task that serves none waits.

For example, for a recipe app: first contact is opening it and seeing something useful with no setup; the core use is finding a recipe and following it while cooking; coming back is finding last week's recipe again. The tasks follow: a start view with sample recipes, a step-by-step cooking view, and saved history.

Keep the whole result runnable at every point. Fold each finished task into the working result before starting the next layer, so that stopping at any moment still leaves something a user can use.
