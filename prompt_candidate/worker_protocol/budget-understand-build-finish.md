Spend your effort in this proportion:

- One fifth understanding: run what already exists, read the relevant code, and work out how the result will be used.
- Three fifths building: make the change in small steps and run it after each one, so it is never broken for long.
- One fifth finishing: check speed and resource use at realistic sizes, then leave a short note of what changed and how to run it.

When time runs short, shrink the building share, never the understanding or finishing shares.
